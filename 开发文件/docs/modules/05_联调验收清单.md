# 三模块联调验收清单

## 第一轮接口冻结

- [ ] 三人确认接口字段、金额字符串、时间、单位、null语义和错误码。
- [ ] A确认CalculationRequest能容纳原公式必需输入，特别折扣、材料口径、工段计件和制造费用版本。
- [ ] B确认日报粒度、重复来源判断、修订号、数据回放和费用池依赖。
- [ ] C确认AI作用范围、版本固定、证据引用、秘书回答结构和反馈审核。
- [ ] 合成案例跑通后冻结1.0.0；draft阶段修改同步契约、示例和文档。

## 贯穿全流程的固定案例

examples中的QY-DEMO-001是单规格、收入与费用已确认的合成案例：报价100元、数量100、折扣0。预期材料5000、人工2000、制造1000；实际材料5500、人工2180、制造1000。管理100、销售50、财务20；经营费用开关开启。

| 结果 | 预期 | 实际 |
| --- | --- | --- |
| 收入 | 10000.00 | 10000.00 |
| 生产成本 | 8000.00 | 8680.00 |
| 生产毛利 | 2000.00 | 1320.00 |
| 毛利率 | 0.200000 | 0.132000 |
| 经营利润 | 1830.00 | 1150.00 |

毛利差额−680.00；毛利率差−0.068000即−6.8个百分点；相对下降0.340000；风险severe。预期材料采用BOM标准用量1000、价格5、损耗0；实际净耗用1100、价格5。人工预期20×100，实际21.8×100。制造费用池1000、总工时100、该订单工时100；池已关账。所有费用零项均明确确认。

此样例scope为整单、completed但尚未settled，因此final_profit=null。只改变settlement_state为settled且所有确认通过时，final_profit=1150.00。以此避免前端把毛利或未结算利润显示为最终利润。

## A模块

- [ ] 输入固定案例得到上述结果和可定位证据。
- [ ] null折扣不变成0；损耗=1拒绝；实际净耗用不二次加损耗。
- [ ] 整池分摊守恒，单订单取值与整池结果一致。
- [ ] 经营费用缺一项时management_profit/final_profit为null。
- [ ] 不同数量、期间、税/成本口径比较返回不可比原因。

## B模块

- [ ] 同一天两单并存，不互相覆盖；重试批次不重复计入。
- [ ] 修订日报后生成新快照，旧快照仍可按ID读取。
- [ ] 16日补录12日资料，当前视图更新；13日known_at历史视图保持原结果。
- [ ] 修改共享池会重算全部受影响订单，旧任务不能覆盖新结果。
- [ ] 分页、汇总、趋势属于同一view_id，显示缺失覆盖与重算状态。
- [ ] 币种/口径不同分组；多订单毛利率按总毛利除以总收入计算。

## C模块

- [ ] “赚多少”“少赚多少”“今天优先看谁”“原因是什么”“缺什么资料”五类问题返回适配内容。
- [ ] 所有金额、单位和引用与固定快照一致，不重新计算或编造原因。
- [ ] 未接入503、队列满429、输出引用无效failed、取消和旧context状态正确。
- [ ] 多订单范围过大时说明覆盖并按需检索，不虚称已分析全部订单。
- [ ] 反馈修订保留原答，未审核内容不能进入训练集。

## 整合到当前网站

- [ ] 首页调用B创建/读取视图；所有列表、统计与曲线复用view_id。
- [ ] 单订单页从B读取A计算快照；毛利、经营利润、预测和已结算利润分别展示。
- [ ] 明细页按snapshot输入版本定位原始来源，不误读最新修订的值。
- [ ] AI请求只传范围ID与问题，服务端从B取事实；前端不提交权威金额。
- [ ] 正式模式移除前端metrics.js核算路径，保留明确隔离的演示模式。
- [ ] 模型服务中断不影响订单核算与数据查询。

## 当前交付边界

本包交付接口设计、机器可读Schema和合成示例，不安装后端框架、不改现有服务、不启动训练。现有网站页面及演示数据保持可用。业务尚未确认的口径通过null、estimated、issues和scope处理，不影响三人先使用确定的合成案例分别开发。
