# 原工程目录拆分说明

本次直接移动原工程文件，采用三个目录，不再自动导出副本。

| 目录 | 内容 |
| --- | --- |
| 运行文件 | dist 页面、runtime 服务运行包、serve.mjs、start-website.mjs、启动网站.cmd、paths.mjs 和第三方许可 |
| 开发文件 | server 源码、scripts、tests、docs、examples、contracts、依赖清单与锁文件、node_modules、Python 虚拟环境和开发辅助资料 |
| 存储文件 | data 业务数据、output 调试结果、日志；整体排除在 Git 之外 |

根目录保留 Git 管理目录、CI 配置、使用说明、转发 npm 命令的 package.json，以及双击启动入口。这些入口只转发命令，不额外保存网站代码。

## 启动与开发

在工程根目录双击启动网站.cmd，或进入运行文件双击启动。需要 Node.js 20 或以上。原账号、订单和历史直接从存储文件/data/imports读取，无需再次导入。模型服务仍独立部署。

在工程根目录执行 npm run setup 安装开发依赖，npm run build 构建后端，npm test 运行测试。已有依赖已移动到开发文件/node_modules，不重复安装。后端源码在开发文件/server，前端源码直接在运行文件/dist修改。构建结果只写运行文件/runtime，不在开发区再保留一份运行包。

Python 合约校验可运行：开发文件/.venv/Scripts/python.exe 开发文件/contracts/validate_examples.py。虚拟环境移动后使用 python -m pip，避免旧 pip.exe 内嵌的绝对路径影响运行。

## 数据位置

默认位置是运行文件的同级目录：存储文件/data/imports。QIYING_DATA_DIR 环境变量可指定其他 imports 目录。运行时数据、账号密码哈希、压缩历史均保留；迁移前后按文件名、大小和 SHA-256 核对。

存储文件为私有资料，不提交到公开仓库。需要备份或恢复时先停服，只操作存储文件/data。正常浏览、构建和测试不自动生成工程分发副本。

## 历史资料中的路径

旧文档中的 server、scripts、tests、docs、examples、contracts 现在位于开发文件内；dist、runtime 和运行入口位于运行文件内；data、output 及日志位于存储文件内。旧版导出脚本及其测试已撤下，原实现仍能从 Git 历史恢复。

不要把运行文件单独搬离另外两个目录后继续用于原有数据；完整工程需要保持三个目录同级。
