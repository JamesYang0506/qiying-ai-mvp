# 团队协作约定

## 任务和分支

在 GitHub Issues 中记录认领任务：目标、负责人、输入、输出、验收条件和预计完成日期。一个任务指定一位主要负责人，协作者可同时参与。

从最新 `main` 创建任务分支，例如 `feat/data-validation`、`feat/file-upload` 或 `docs/data-dictionary`。通过 Pull Request 合并到 `main`，说明改动、验证方法和未解决事项，建议由另一位同伴检查后合并。

以上是团队协作约定，当前没有配置强制审核或分支保护。

## A B C 边界

- C 负责上传页面及用户操作；A 负责文件解析、解析错误处理和流程调用。
- A 向 B 提供解析后的各表及来源信息；B 负责业务字段识别、标准化、校验和计算。
- B 输出利润明细、检查证据、异常及计算可用状态；A 负责调用大模型；C 负责展示。
- 修改公共字段或模块接口前，在对应 Issue/PR 中与使用该接口的成员确认。

## 提交前检查

- 检查暂存差异，确认没有企业原始数据、实际 API 密钥或凭证。
- 计算改动用已确认的手工算例核对；数据处理改动检查缺失、重复和关联失败的处理。
- 修改接口时同步文档及样例；模拟数据明确标注。

## 开发顺序

先确认数据样本、字段含义及手工算例；再用模拟输入连接各模块。随后替换为获准使用的真实样本，核对结果，最后完成现场演示及异常情况检查。
