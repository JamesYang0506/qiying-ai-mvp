# 订单监测首页：设计与 CC 交接大纲

日期：2026-10-17。用途：交给 CC 实施首页专题，与 A/B/C 模块并行推进。本文交付设计及开发大纲，不包含本轮首页产品代码修改。

## 1. 已确认的设计方向

首页负责从多笔订单中找出今天值得优先核查的订单；单订单页面负责解释计算过程与原始记录。

用户已确认：

1. 优先展示“今天比昨天恶化最明显的订单”，保留累计严重偏离的提醒。
2. 根据数据变化生成不同的核查建议，每笔最多三条，不固定套用同一组原因。
3. 首版只做建议展示和查看依据，暂不做负责人、截止日期、整改任务或执行状态。
4. 配色与原网站一致：深蓝导航、蓝色强调、浅色页面背景、白色卡片；不是深色内容页面。
5. 增加图表，采用“实际与同进度理论毛利趋势＋当日毛利率分布环形图”。
6. 保留“重点订单选择→联动建议→原始依据”和全部订单列表。

## 2. 页面结构

由上到下分为五层，沿用现有应用导航，不增加尚未实现的企业切换、登录身份、通知和任务菜单。

### 第一层：标题与监测范围

- 标题“订单监测”，副标题“先看今天的变化，再找到值得核查的原因”。
- 业务截至日期、数据来源、理论模式及数据更新入口。全页共用日期和模式，不能各区域各算一套。
- 区分内置演示与已导入数据；没有导入数据时给出导入入口，不以演示数据填充真实订单列表。
- 说明使用的修订版本集合；查询失败保留明确错误状态，不能把旧数据改标为新日期。

### 第二层：四张概况卡片

| 卡片 | 含义 | 附带说明 |
| --- | --- | --- |
| 累计实际生产毛利 | 当前对照集合截至选定日的实际生产毛利总和 | 纳入订单数量 |
| 同进度理论生产毛利 | 同一集合、对应合格产量的理论生产毛利总和 | 理想/预算模式 |
| 累计比理论少赚 | 同进度理论减实际 | 正值少赚，负值多赚；不是“今日恶化金额” |
| 今日表现恶化 | 符合前后日比较条件且当日毛利率下降的订单数 | 比较数量、排除数量 |

三张金额卡必须使用同一可比集合，保证“理论−实际＝差距”。若另展示全部已知实际毛利，必须单独命名并说明集合，不能混用现有 portfolio 的不同覆盖汇总。

卡片下展示覆盖说明：监测总数、可核算数、可比数、前后日可比数、待补齐数和排除原因入口。空集合显示“暂无可比数据”，不显示具有经营含义的零。

### 第三层：两张图表

**左：累计实际与同进度理论生产毛利趋势。**

- 蓝色实线为实际，绿色虚线为理论；轴标明日期和金额单位。
- 选择短期窗口只改变曲线显示区间，累计仍从各订单开工日计算。
- 同一条对照曲线的实际和理论使用一致集合。首版推荐固定窗口内每个日期均可比较的订单交集，显示纳入/排除数量；卡片若采用另一集合，应明确标注，不把图表端点当作卡片总额。
- 无共同集合时显示缺项原因；缺失点不连成零值。悬停/触摸可读金额，选择日期后全页联动。
- 不复制效果图中的收入与利润曲线：本项目重点是实际与同进度理论利润的差距。

**右：当日生产毛利率分布环形图。**

- 分组边界互斥：≥30%；10%≤毛利率<30%；0%≤毛利率<10%；<0%；无法计算。
- 图例展示笔数和占监测集合比例；零收入、缺成本等归入无法计算，未开工订单单独说明。
- 点击分类筛选全部订单列表；不改变上方总体统计和重点关注的范围，界面注明“列表筛选”。
- 这是毛利率分布，不是相对预期风险分级，不能直接把低毛利率判定为严重异常。
- 灰色表示资料不足，蓝/绿/橙/红表示对应的已知分布，配文字标签。

### 第四层：重点关注＋联动核查建议

**左侧重点关注：** 默认显示前3至5笔今日恶化订单。展示订单/产品、当日毛利率、较昨日变化（pp）、单位合格品成本变化及主要数据线索。点击切换右侧建议。

没有今日恶化时显示明确的平稳状态；累计严重偏离和资料待补齐另设提醒，不凑进今日恶化排名。存在累计亏损时保留亏损标签。

**右侧核查建议：** 每笔最多三条，每条包含“数据变化＋核查建议＋查看依据”。没有足够证据时只显示一至两条，不凑满三条。

| 方向 | 触发依据 | 建议内容 |
| --- | --- | --- |
| 材料价格 | 可比较材料实际单价上涨及价格影响增加 | 核对采购批次、供应商报价、入库单价和录入值 |
| 材料耗用 | 相同口径单位合格品净耗增加 | 核对领退料、标准重量、不良数量及净耗口径 |
| 补料/补产关联 | 补料或补产比例变化、关联说明不足 | 核对用途、生产关联、是否已含加工与净耗；不重复扣成本 |
| 人工 | 单位合格品人工费用增加 | 核对工价、计件量、合格产量与费用归属 |
| 能源/制造 | 已归属的单位制造费用增加 | 核对所属日期、订单及分摊依据；无工时数据时不声称停机低效 |
| 数据核查 | 缺项、补录或口径变化妨碍比较 | 指出具体缺什么或何处更新，不生成经营恶化结论 |

建议由规则和已验证事实生成，首版不依赖 AI。金额由服务端提供；“耗用增加”是事实线索，“浪费”“操作不当”等属于待核验原因，不能自动断言。

依据入口保留订单、业务日、修订、基线模式、费用类别/材料编号和证据ID，跳转到现有单订单下钻或原始记录视图；返回首页保留筛选与选中订单。

### 第五层：全部订单

字段：订单/产品、完成进度、累计实际生产毛利、同进度差距、当日毛利率、较昨日变化、资料状态、查看分析/建议/缺项。

支持订单/产品搜索，今日恶化、待补齐及分布分类筛选。默认按今日毛利率下降排序，无法比较者明确标记；同值按订单ID稳定排序。排序和搜索不修改汇总集合，列表标明筛选后数量。

## 3. 今日恶化的计算原则

以下作为 CC 实施时的首版技术默认，必须写入测试和页面口径说明：

- 比较 D 日和 D−1 日的**当日**生产毛利率，不比较两个累计毛利率，也不以累计差距增长直接判断恶化。
- `marginChangePp = (dailyMarginD − dailyMarginPrevious) × 100`。负值表示下降；首版按未四舍五入值排序，显示值若不足0.1pp须保留更多精度或显示“下降不足0.1pp”。暂不新增未经确认的预警阈值。
- 两天均有明确报工、收入>0、生产成本完整且口径/版本可比才参与；没有昨日记录不能默认为停产或零利润。
- `unitCost = dailyProductionCost / dailyQualifiedQuantity`，两天合格量>0才计算单位成本变化。零产量仍有费用可以展示负毛利，但不能强行计算单位成本。
- 只选定一次订单修订与基线集合，再完成整个请求，避免查询过程中版本变化导致各区域不一致。
- “生产变化”和“补录带来的信息变化”分开。当前 evaluate 的业务日和可见截止耦合；在没有独立 known_at 支持前，不能声称已经按统一信息截止重建昨日。
- 对可检测的迟录、修订差异，保守标记为“资料更新待核查”并排除纯经营恶化判断；无法可靠识别时先显示不可比较。后续由 B 的 known_at/快照能力替换，不能悄悄把该限制藏起来。
- 材料/费用总额变化可能来自产量变化，建议要使用单位量或同产量影响，不能仅凭总费用增加判断效率下降。

**验收：** 基线记录清楚，其他成员已有功能保留。

### H1：页面骨架与合成适配

- 独立首页模块，沿用蓝白样式，完成五层布局。
- 用明确标记的合成数据实现订单选择、建议联动、搜索、分布筛选和空状态。
- 不从设计稿抄取静态数字冒充接口结果，不把该阶段称为业务功能完成。

**验收：** 桌面和窄屏可用；所选订单与建议对应；没有遮挡或截断。

### H2：服务端汇总和趋势

- 复用核算器与最新数据模型，增加只读首页适配接口。
- 实现相同集合的三张金额卡、覆盖说明、固定集合趋势与当日分布。
- 请求开始选定版本，输出版本及排除原因；前端不逐单并发调用后自行求和。

**验收：** 理论−实际＝差距；分布数量之和与其监测集合一致；缺项与空集合不误算零。

### H3：前后日比较及重点关注

- 实现第3节的比较规则、单位成本、稳定排序和累计严重偏离提醒。
- 专门处理未报工、停产、零收入、缺昨日、迟录和修订变化；不把补录误认为生产恶化。

**验收：** 今日恶化与累计差距是独立字段；前后日不可比较时有原因，不产生伪排名。

### H4：建议与证据下钻

- 按有效数据生成最多三条建议，材料价格/耗用优先但不强套类别。
- 附来源与比较范围，衔接现有单订单下钻；保留首页返回状态。
- 无证据、不支持的归因或缺项采用待核查提示，不输出确定原因。

**验收：** 不同订单得到不同建议；补料不重复计费；引用能定位记录；不依赖 AI 服务。

### H5：联调与交付

- 增加合成的多订单、跨日期、修订和缺项测试，核对数据覆盖及错误状态。
- 复算本机中底案例，确保 A 的金额无回归；资料和计算输出留在本机。
- 服务端修改后 `npm run build`，重启并验证实际运行的 bundle；检查一键启动。
- 更新 README 与接口状态，每个阶段验证后提交 Git；推送、合并与发布按用户具体授权执行。

**验收：** 首页、单订单和证据金额一致；全页日期/基线一致；旧响应不会覆盖用户新选择。

## 6. 必测情形

1. 累计差距增长但当日单位成本、毛利率稳定：不判为今日恶化。
2. 产量增长导致总材料成本增加但单位净耗不变：不建议“耗用失控”。
3. 材料价格稳定、人工增加：建议应切换到人工核查。
4. 缺昨日、零收入、零合格量、明确停产：分别说明，不用零值凑比较。
5. 补料已含净耗：不重复扣成本；关联不足只提示核查，不自动补造记录。
6. 补录/修订变化：信息更新提示不与经营恶化混同。
7. 已知实际集合与可比集合不同：三张卡使用同一集合或明确拆开展示。
8. 环形图阈值0%、10%、30%，负值、缺失与未开工：分类互斥、覆盖清楚。
9. 快速切换日期、基线、订单，接口失败：旧响应不会误标为新范围。
10. 空数据、全部缺失、全部改善、同分排序、长订单名称、窄屏：页面仍可理解并可操作。
