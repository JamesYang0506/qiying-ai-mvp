# 代码、开发环境与业务数据分离

当前开发目录继续作为唯一日常开发入口。通过复制导出三个用途明确的目录，不搬动原来的数据或依赖，现有网站仍按原方式启动。

| 目录 | 内容 | 用途 |
| --- | --- | --- |
| 01_干净运行版 | dist、runtime、启动入口及许可说明 | 给使用者启动网站；不带已有账号和订单 |
| 02_开发源码 | Git 已提交的源码、运行包、文档、测试、依赖清单 | 交接开发；修改服务端后重新构建 runtime |
| 03_数据备份 | data 全部内容，包括订单、账号密码哈希和压缩历史 | 私有备份；不要提交到公开仓库 |

node_modules、Python 虚拟环境、Git 历史、调试截图和日志留在原开发目录。开发源码中仍保留必要文档和示例；这些文件属于开发资料，而运行版只保留网站启动需要的内容。

## 重复导出

在原工程中先保存 Git 提交，再运行：

```powershell
npm run export:clean
# 需要额外备份本地业务数据时：
npm run export:backup
```

默认生成到工程旁的 `项目分发/企盈智擎-时间-提交号/`。也可指定新目录：

```powershell
node scripts/export-workspace.mjs --with-data --output "D:\项目备份\企盈智擎新版本"
```

目标目录必须在工程外且尚不存在；工具不会覆盖旧备份。代码按 Git 提交导出，未跟踪文件不会混入。工具拒绝导出包含业务数据、环境密钥或大模型权重的提交。数据按现有压缩形式复制，不解压历史。

导出期间尽量不要导入或修改订单。工具会检查数据前后是否一致，发生变化则报错；原文件不受影响。只有 manifest.json 中 verified 为 true 的目录才是完整导出；失败后另选目录重试。清单包含版本、文件数量和 SHA-256 校验值。

## 使用与协作

运行版需要 Node.js 20 或以上，双击启动网站.cmd，无需安装开发依赖。没有恢复备份时它是空网站，需要注册并导入订单；AI 模型服务仍需独立配置和运行。

组员优先使用 Git 克隆仓库共同开发。离线交接可发开发源码目录，对方执行 npm ci；修改后端后执行 npm run build。不要同时修改导出副本和原工程，以免版本分叉；新版本重新导出即可。

## 恢复数据

先关闭目标网站，备份目标原有 data，再把 03_数据备份/data 复制到运行版根目录。运行版、源码和备份应使用同一提交对应的版本，避免旧运行包读取新数据。数据备份涉及账号与订单，应私下保存，不随公开代码分发。

本次分离是生成独立副本，不改变原工程的数据路径，也不删除原目录中的任何内容。后续确认备份和运行版可用后，再单独决定是否清理缓存或旧副本。
