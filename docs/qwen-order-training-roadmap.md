# 订单分析训练建议

状态：已暂缓。以下内容保留为未来研究规划，当前产品未提供训练集导出、专家标注包或微调流程；普通数据导出仍可使用。

当前：RTX4060 Laptop 8GB；Ollama qwen3.5:4b，GGUF Q4_K_M。目标是制造订单分析和高层建议。

## 推荐路线

1. 公式引擎计算成本和利润，大模型解释、引用依据并给出有条件建议。先做基线评测，避免让模型记忆动态金额。
2. 建历史订单与规则资料库，分析时检索相近订单、标准成本及适用时期规则（RAG）。知识更新先更新资料，不反复训练。
3. 积累人工审核案例，再做SFT，先尝试LoRA/QLoRA，不从零预训练或做4B全参数训练。
4. 在同一独立测试集比较原模型、RAG和微调效果，出现可重复改进再部署；保留原模型可回滚。

如果目标是预测交期、实际耗用或返工率，要单独建设对应标签与预测模型评估，不能把模型解释能力当作预测能力。

## 数据收集

| 资料组 | 关键字段 |
|---|---|
| 订单 | 订单号、产品、客户代号、日期、数量、价格、折扣、税口径、交付与回款条件 |
| 成本 | 采购价、领补退料/回收料/在制品、工资、能耗、包装运费、开发与资产摊分、费用期间和完整分母 |
| 生产质量 | 分码产量、不良、返工、补料、质检阈值、工段批次、实际工艺参数 |
| 审核结果 | 生产毛利、经营净利、异常类型及严重度、依据编号、核验状态及更正记录 |
| 决策后果 | 当时建议与实际决定、原因、最终结算、交付、回款结果 |

订单主表和成本明细必须关联。区分下单、生产、出货和收入确认；单位、税口径、期间、直接归属和分摊不能混用。当前税口径和外链分摊等未核实，相关数字只能作为带状态的试算事实，不能作为真实标准答案。

## 一条高质量训练样本

输入：当时可见订单资料 + 程序计算结果 + 可信化状态 + 检索依据 + 分析问题。

输出：经人工审核的简明结论 + 异常类别/等级 + 每条有效引用 + 行动建议与条件 + 待确认事项。

元数据：order_id、snapshot_id、公式版本、资料截至日期、标注/审核人和时间、任务类型、脱敏与来源授权状态、数据集划分。成本错误、模型草稿、未核验疑点均不得直接变成已确认标签。未知案例可以教模型保留未知。

建议先整理约50—100笔多样化订单用于试点评测，再整理约200—500条高质量人工案例做小实验。这是工作量规划，不是效果保证或固定最低门槛。覆盖盈利、亏损、正常、缺失、零值、跨月分摊和重复费用疑点，不能只收异常订单。

## 防止评测“对答案”

同一订单、补单、重复导出和多条问答必须属于同一划分。按订单组及时间留出测试订单，避免近重复样本泄漏；视推广目标增加未见客户/产品测试。一个可选起点为训练/验证/测试约70/15/15，小数据先保证测试覆盖。接单前分析不得输入当时未知的最终利润、质量或回款结果。

考察金额引用错误率、引用有效率、异常识别精确率/召回率、关键风险漏报、把待核验误判为已证实的比例、结构化成功率、专家建议评分及响应时间。保留正常样本衡量误报，不只看训练loss。

## 8GB显存配置建议

Ollama主要用于本地推理和部署；常规SFT应使用训练框架支持的原始模型权重，不直接训练Ollama量化GGUF。训练完成后再转换/量化部署。

8GB可尝试小规模4bit QLoRA，但不保证任何上下文和实现都可训4B。先用几十条样本、短上下文（如1024，成功后再试2048）、batch size 1、梯度累积和梯度检查点验证显存与吞吐。先做文本订单任务，按Qwen3.5结构选择目标层与冻结策略，不能照搬旧Qwen脚本。推理服务和训练不要同时占显存；OOM先缩短上下文或减小模型，必要时换大显存机器。

建议独立训练环境，可考虑Linux/WSL2；固定框架与驱动依赖版本。LLaMA-Factory已有Qwen3.5支持。本次未安装训练环境或启动训练。
