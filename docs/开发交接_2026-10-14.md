## 3. 已完成的用户流程

### 3.1 导入、适配与计算

1. 选择 `.xlsx` 或标准 `.json`，输入上限10MB。
2. Excel 字段、数值、单位及材料/日报布局明确时，自动适配并计算，不弹确认框。
3. 不明确时进入预览，只优先显示有问题字段，可切换显示全部字段；调整位置和单位后需重新预览。
4. 人工确认完成的映射方案保存在该浏览器本地，后续同结构文件可自动复用，但始终读取新文件数值。
5. 服务端在保存前查重；成功计算保存本机快照，页面提供追溯和导出。

支持标准模板按表头读取、列顺序调整；中底成本表的订单与17项费用支持标签/同义词识别、位置和每双/整单单位调整。整单费用按订单数量换算，不用缓存旧订单数值。

**支持范围仍有限**：中底明细表需保留“原订单用量”“补单用量”“生产周期”名称；材料预览范围 B3:K17，生产周期 A6:L43；日期明细实际读取第8至43行。任意布局不是通用支持范围。范围外材料或日报明细会阻止导入，包含公式材料行和文本/公式日期，避免静默漏算。

### 3.2 历史记录

每次保存的订单分析按时间逐条显示，可切换按订单汇总，搜索编号、产品或客户，筛选模拟/导入数据。读取历史不重算、不覆盖当前分析，也不自动调用模型。

历史回看有“返回上一个历史页面”和“返回当前分析”；大厅自身不重复显示返回大厅按钮。

曾出现“上一笔订单没有进入历史”的现象：实际快照已保存，同编号被折叠成版本，只显示最新版。已改成默认逐条展示，不能把这个旧现象当成当前仍未修复的存储丢失。

### 3.3 删除与恢复

历史每条记录有“删除记录”，确认框显示编号、产品、分析时间和版本。删除范围是指定订单的指定分析版本，不是该编号全部版本。

“展示方式 → 回收站 → 恢复记录”可以恢复。这里是网站内部回收站，不是 Windows 回收站。原始 Excel 和原计算快照不删除，仅写入删除标记；关联模型分析仍保留。

同一快照有多笔订单时，删除一笔保留其余。当前快照所有订单都删除时，当前分析为空，不自动把更早记录当成最新。删除后页面重新载入，避免已删除内容留在当前分析中。已删除记录不能从正常历史、导出或模型准备接口继续使用，须先恢复。

### 3.4 查重（最近完成）

按订单有效投入指纹匹配，再核对计算与分摊结果，不能只比文件名、编号或利润总额。

- 完全重复：不新增、不覆盖当前，提示“发现重复订单”，可查看已有记录。
- 同一订单的数量、报价、折扣、逐项成本或过程数据变化：保存新版本。
- 文件改名、排版调整、表内保存利润答案变化：不作为新业务数据。
- 重复数据只在回收站：提示恢复原记录，不自动恢复或新增副本。
- 批量部分重复：跳过重复订单，保存其余新/变更订单，提示跳过项；本次当前快照只包含本次新保存订单，其他订单在历史查看。
- 已有重复记录不自动清理；正常记录优先于回收站副本。
- 公式版本不同允许重新分析；查重与写入使用同一进程锁，避免并发重复保存。

两个已修复的关键误判必须保留回归测试：同文件校正映射/单位应允许新计算；同费用池新增订单导致最大余数尾差改变本单分摊，应保存新版本。报价与折扣相抵、净价不变，也不能冒充投入完全相同。

旧中底快照用保存的原始投入摘要兼容比较；旧标准模板未保留完整输入时仅保守匹配文件/原 input_hash 与结果。不能为了提高命中率只按相同利润拦截。

**当前订单身份限制**：中底表没有独立业务订单编号时采用 `SRC-款号`，如 SRC-A-011。同款同投入的两笔真实订单不能靠款号区分；应优先补充真正的订单编号/批次映射，不应擅自造编号或放松为仅凭款号查重。

## 4. 计算口径：必须保留的边界

### 4.1 严格标准引擎

`profit_model/engine.py` 使用 Decimal，金额输出字符串，最终按分舍入；缺失为 null，不能补零。实际/预测分开。

- 收入：单价×数量−折扣；有订单行时按行汇总，不重复加订单头收入。
- BOM 材料：在损耗定义明确时使用数量×单价/(1−损耗率)。
- 实际净耗用材料：耗用×单价，不再重复加损耗。
- 人工：计薪数量×对应单价，需适用口径。
- 费用池：按期间费用池和完整分母分摊；整数分最大余数处理尾差，保留未分摊余额。
- 生产毛利：收入减生产成本；需完整度、归属和范围检查。
- 订单管理利润：生产毛利再减归属明确的管理/销售/财务等费用，默认关闭；`management_enabled=true` 才启用。不是财务报表净利润。

### 4.2 中底成本源表参考试算

`profit_model/eva_source.py` 从配方、分码 SOP 重量、原单/补单数量及逐项费率独立计算。

- 配方均价＝Σ(配方用量×单价)/Σ配方用量。
- 材料费用＝配方均价×各码 SOP 每双重量×对应数量，分别归集原单和补单。
- 折后收入＝(订单单价−每双折扣)×订单数量。
- 生产毛利试算＝折后收入−材料总额−人工及加工费用。
- 经营净利试算＝生产毛利试算−已列行政管理/销售等费用。

这条试算保存在 `source_analysis`，与严格核算字段分开；表内能耗等已有费用可以先使用，但保留来源/分摊待核验。外链费率可使用文件已有缓存，标明来源未核验；无缓存的未知项不能补零。

原表利润、利润保存值和费用汇总不得直接或间接作为成本输入。先独立计算，再读取保存利润作对照。位置映射不改写原文件，不执行宏或任意公式，不自动连接缺失外链工作簿。

首页经营净利试算不等于正式财务净利润。源表给出参考利润，不意味着严格利润的材料、工时、费用归属、税和完整度已经满足，不能为消除“依据待补”强行开启或补齐严格口径。

## 6. 程序结构与接口

| 文件 | 职责 |
|---|---|
| server.py | 本地HTTP路由、导入、查重后保存、导出、模型分析接口 |
| profit_model/engine.py | 严格标准数据计算、完整度、分摊 |
| profit_model/eva_source.py | 中底表独立复算、受限公式、来源和事后对照 |
| profit_model/excel_import.py | 预览、标签识别、字段映射、单位换算、自动方案和结构指纹 |
| profit_model/duplicates.py | 逐单投入指纹、旧快照兼容比较、结果一致性检查 |
| profit_model/history.py | 历史索引、单订单读取、删除标记与恢复、可见性过滤 |
| profit_model/trust.py | 四类可信化规则，差异/待核验/通过 |
| profit_model/ollama_client.py | Ollama本地调用、结构和事实引用校验 |
| profit_model/analysis_gateway.py | 从已保存订单准备模型上下文、单独保存建议 |
| web/index.html / style.css | 页面结构、样式、弹窗和图表布局 |
| web/app.js / source.js | 页面状态、通用计算展示、源表试算/图表/来源 |
| web/import.js / history.js | 自动导入与查重提示、历史与回收站交互 |

主要路径：Excel/JSON → 读取与适配 → 标准输入/源表复算 → 引擎 → 查重 → 保存快照 → 前端展示。AI仅接收已保存订单事实，不能替代金额计算。

接口详见 [interfaces.md](interfaces.md)。尤其注意：

- `/api/auto-import-xlsx`：自动成功是 `status=imported,result=...`；需预览是 `needs_review`；全重复是 `duplicate,matches=...`。
- `/api/calculate`、`/api/import-xlsx`、`/api/import-reviewed-xlsx`：成功仍返回原结果对象；全重复返回 `status=duplicate`，调用方不能无条件 accept 为计算结果。
- 部分重复：`snapshot.duplicates_skipped` 标明跳过项。
- `/api/preview-xlsx` 只读；人工确认导入需校验同一文件hash、映射及confirmed。
- `/api/history`、`/api/history/{sid}?order_id=...`：正常历史索引和单订单读取。
- `/api/history/trash`、POST `/api/history/delete`、`/api/history/restore`：回收站；变更需 snapshot_id、order_id、confirmed=true。
- `/api/current`：当前可见快照；无可见订单返回 current=null。
- `/api/export`、`/api/ai/status`、`/api/ai/analyze`：普通结果导出和模型接入；训练导出接口已移除。

## 10. 接续开发建议

以下是建议，不是已获授权的新开发任务；新聊天先确认用户下一步目标。

1. 优先明确独立订单编号/批次，解决同款不同业务订单的身份区分。
2. 继续核验成本重复归集、外链依据、税口径和不良/补单差异。
3. 建立接单前测算基线、过程快照与偏离阈值，再实现持续预警；先用规则验证，不急于训练大模型。
4. 根据实际新增表样扩展材料/日报自动适配，保留异常提示和读取追溯。
5. 需要共享当前功能时，再同步GitHub并构建新Release；先保留业务数据、校验下载包数据隔离。
