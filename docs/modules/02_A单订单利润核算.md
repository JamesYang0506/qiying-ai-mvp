# A模块 单订单利润核算

## 目标与边界

对一笔订单的预期、实际及偏差提供可追溯结果。核算支持整单、截至某日累计及当日三个范围。A只计算，B决定使用哪些资料并保存结果；AI不能回写A的计算值。

## 公式与输入

依据最新公式原文及已确认毛利分级。本文使用通用变量，下列输入字段在OpenAPI中可查。

| 项目 | 公式 | 输入与约束 |
| --- | --- | --- |
| 收入 | `R = Σ(price × quantity − discount)` | revenue_lines；单价、数量、折扣任一未知则相关收入不完整；订单头收入不能重复相加 |
| BOM材料 | `Cmat = Σ(standard_quantity × weighted_price / (1 − loss_rate))` | material_basis=bom；损耗率0≤L<1且有依据 |
| 实际材料 | `Cmat = Σ(net_quantity × weighted_price)` | material_basis=actual_net；净领用口径需确认，不再次叠加BOM损耗 |
| 人工 | `Clab = Σ(piece_rate × payable_quantity)` | labor_lines按工段归集；不能随意按总产量均摊工资 |
| 制造费用 | `Cmfg = Σ(Mt / Ht × hit)` | 由allocate_manufacturing提供分摊行；M/H/h同期间且有完整分母 |
| 生产毛利 | `GP = R − Cmat − Clab − Cmfg − Cother` | Cother仅含企业确认的其他生产费用，无此项时有明确零确认；不重复归集 |
| 单位毛利 | `UGP = GP / Q` | Q>0且单位一致 |
| 毛利率 | `GPM = GP / R` | R>0，否则为null |
| 经营净利 | `NP = GP − Cmgmt − Csales − Cfin` | management_enabled=true且三项费用归属/完整性已确认才计算 |

当前不计模具摊销。生产能耗若已进入制造费用池，不能再作为其他生产费用扣一次。实际材料法和BOM法的结果可分别展示，但一次利润核算只能选择一种材料成本口径。

## “最终利润”如何输出

为满足页面展示，又保留业务含义，统一返回四个不同字段：

- `gross_profit`：当前范围的生产毛利。
- `management_profit`：相关费用完整时的经营净利管理核算值；不是审计净利润。
- `forecast_profit`：由独立预测输入/版本给出的预计完工经营利润，首版未建立预测方法时为null。
- `final_profit`：只在整单、已结算、收入成本与经营费用完整且经确认时，等于management_profit；其他情况null并解释缺失条件。界面显示“已结算订单经营利润”，不误标为财务报表净利润。

预期输入也独立核算gross_profit和management_profit，可用作整单目标；最终已结算字段只用于actual。预测不能用未完工累计成本直接减整单收入得到。

预期基线写入提供stage_policy和stage_inputs。首版只支持明确的阶段输入explicit_stage_inputs，按匹配的Scope选择；none表示只有整单预期，生产期间无匹配阶段基线则不可比。暂不实现自动等比例缩放，后续确定企业阶段归集规则后再扩展策略枚举。B负责挑选候选，A负责核对Scope一致性。

## 对照与风险

`profit_delta = actual.gross_profit − expected.gross_profit`；`margin_delta = actual.gross_margin − expected.gross_margin`；`relative_decline = (expected.gross_margin − actual.gross_margin) / expected.gross_margin`。

只有双方范围一致、数字有效、quality符合明确的比较要求才返回comparable=true。试算对照comparison.quality=estimated，并持续展示试算标记；不因两边都有数字就视为正式可比。基线≤0不使用相对下降规则；profit_delta仍可在范围一致时提供。

预期为正时：actual优于expected→better；下降0～10%→normal；>10～20%→attention；>20～30%→key；>30%→severe。基线零/负、缺失或不可比→not_applicable，说明原因。负毛利单独输出 `loss=true`，不可被不可评级状态掩盖。

成本差额逐类列出 `actual − expected`，并满足 `profit_delta = revenue_delta − Σ cost_delta`；如果收入相同，利润减少等于成本超额。缺失类别不能把剩余差额强行命名为返工损失。每个偏差附证据ID，原因只标候选或待核验。

## 费用池分摊接口

`POST /api/v1/profit/allocations/evaluate` 无持久化。池字段：pool_version_id、period、currency、amount、total_hours、targets（order_id、hours）与来源。H=0或Σh>H拒绝；Σh<H允许，但剩余工时必须记录为unassigned目标。

按 `M/H×h` 使用整数分最大余数分摊（并列按稳定order_id排序，unassigned最后），所有订单分摊额＋unassigned_amount严格等于M。必须先全池一起分摊，再取某订单，不对每笔订单独立四舍五入。池尚未关账时标estimated，B将其版本传入所有受影响订单。

## 对外接口

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| POST `/profit/evaluate` | CalculationRequest | CalculationResult；不保存 |
| POST `/profit/allocations/evaluate` | AllocationRequest | AllocationResult；不保存 |

正式查询与保存走B模块。避免A与B各自再建一套订单结果表。

## 开发验收

固定案例：收入10000、预期成本8000、实际成本8680，预期毛利率20%、实际13.2%、毛利差−680、百分点差−6.8、相对下降34%、风险严重。确认经营费用管理100/销售50/财务20后management_profit=1150；未结算final_profit=null，结算且整单范围完整后为1150。

必须覆盖：折扣空与零、BOM损耗缺失/1/负数、实际领料不二次加损耗、工段计件缺失、制造池跨期间或H=0、分摊守恒、Q/R为零、多单位、未知费用、经营开关关闭、已完工未结算、相对阈值边界、基线零/负、成本差额与利润差一致。

建议复用旧项目engine.calculate与comparison规则，增加新契约适配器并逐项验证，不能直接将旧source_analysis参考试算字段映射为complete最终利润。
