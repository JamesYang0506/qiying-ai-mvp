## 3. 业务口径（改计算前必须先读）

- **quote（报价比例核价）**：`revenue = 数量 × 报价单价`；`材料 = revenue × material_pct/100`；`人工 = 数量 ×（备料计件单价＋油压计件单价）+ revenue × production_management_pct/100`；`加工制造 = revenue × energy_pct/100`；`其他生产 = revenue ×（production_loss_pct + defect_loss_pct）/100`；`生产成本 = 四项之和`；`生产毛利 = revenue − 生产成本`；`经营费用 = revenue ×（company_management_pct + administration_pct）/100`；`经营利润 = 生产毛利 − 经营费用`。物流不纳入本轮预算。
- **costs（独立成本）**：`revenue = 数量 ×（单价 − 每双折扣）`，四项成本独立录入，目标毛利率由网站推导；表内另有声明且差值 > 0.01 个百分点时**报错**（与 `quote` 的"只提示"不同）。
- **ratio**：只录目标毛利率，不反推收入/成本。
- **毛利判级（已确认）**：`margin_mode=relative`，`(计划生产毛利率 − 实际生产毛利率) ÷ 计划生产毛利率 × 100%`；`≤10%` 正常、`>10%～20%` 注意、`>20%～30%` 重点、`>30%` 严重，**10/20/30 是右闭边界**；实际优于计划显示"优于计划"但 `status` 仍为 `normal`；计划毛利率 ≤ 0 时相对下降不适用。页面与报告同时保留百分点差 `delta_pp`；判级用未舍入 Decimal，`relative_drop_exact` 保留精确值。
- **质量规则（暂定）**：累计不良率 `≥3%` 提醒、`≥5%` 严重，最低观察量 100；低于观察量只展示实际比例并标记待观察。**报价里的不良品损耗比例是成本预算，不是不良数量率阈值。**
- `method` 只取 `ratio` / `costs` / `quote`；`quote` 的成本字段与 `costs` 的成本金额互斥，同时出现由 `theory_import.py` 的 `mixed_cost_basis` 冲突保护拦下。

## 4. 数据与接口

- 存储：`reports/snapshots/comparison-data/`，子目录 `baselines`、`bindings`、`rules`、`settings`、`records`、`current-records`、`events`、`watermarks`、`handling`；多文件写入用回滚日志 `transaction.json`（进程中断后首次访问自动恢复，**不要人工删除未完成的事务日志**）。备份要备整个 `reports/snapshots`，不能只备 `latest.json`。
- 关键 schema：基线 `baselines/<uuid>.json` = `id/version/created_at/method/business_order_id/batch_id/actual_order_id/product/bound_quantity/is_demo/scope_confirmed` + 规范化后的金额字段；绑定 `bindings/<sid>-<sha256(oid)>.json` = `baseline_id/scope_confirmed`。
- 路由（`server.py:60-67`）：`/api/theory`（建基线）、`/api/theory/preview`（只读预览，不写任何资料）、`/api/theory/bind`、`/api/comparison/check`、`/api/comparison/rules`、`/api/comparison/event`。
- 检测缓存：`_check` 按 `signature = digest([sid, oid, baseline_id, rules.version, scope])` 复用已存记录，因此改基线必须换 `id`（本轮版本收敛保留了这一点）。
