# 订单导入查重

更新日期：2026-10-14。

## 使用

相同订单数据再次导入时，不写入新记录、不覆盖当前分析，页面提示“发现重复订单”，可点击“查看已有记录”。记录已移入回收站时，点击“恢复原记录”恢复已有快照。

同一订单的数量、报价、折扣、逐项成本、材料或生产过程数据发生变化时，仍保存新分析版本。批量输入逐笔匹配：跳过已存在的相同订单，其余订单保存为新快照；页面列出跳过的记录。新快照及当前分析只包含本次保存的订单，其余记录继续在历史中查看。

已有重复记录不自动合并或删除，可以在历史页面单独处理。

## 比较依据

服务端在保存前比较订单编号、有效计算输入及计算/分摊结果，不只比较文件名、订单编号或利润总额。输入包含数量、价格、折扣、成本明细、费用池、订单基数、完整度及适用的材料/日报数据。报价和折扣变化但净价相同，仍属于输入变化；费用池尾差因参与订单变化而改变本单分摊结果，也属于新版本。

字段顺序、明细行顺序、数字的等价写法（例如1000与1000.00）、读取坐标、来源说明和导入方案名称不作为业务变化。表格排版和表内保存利润答案的变化不作为新数据。文件指纹保留用于追溯，不能绕过映射校正后的有效投入比较。

新快照保存 snapshot.import_identity.order_hashes，每笔订单一个完整SHA-256指纹。旧中底成本快照用保存的订单信息、原单/补单材料、逐项费用、日报及报价折扣进行兼容比较；旧标准模板记录没有完整原始输入时，仅在文件指纹或原 input_hash 相同且结果一致时拦截，避免根据相同利润误判。

公式版本不同允许重新分析。已有正常记录优先于回收站中的重复副本。查重与写快照使用同一进程锁，防止并发重复保存。

中底成本表缺少独立业务订单编号时，仍沿用SRC-款号；同款、同投入的两笔真实业务订单需要先补充不同订单编号，系统不能仅凭款号推断其业务身份。

## 接口

POST /api/calculate、/api/import-xlsx、/api/import-reviewed-xlsx、/api/auto-import-xlsx 均在保存前查重。

全部重复：返回 status=duplicate、matches（所有匹配版本和订单）、match（首个匹配版本）。匹配订单含 deleted 标记、版本时间、编号和产品信息，不返回回收站完整数据，也不自动恢复。

部分重复：保留原成功响应格式，snapshot.duplicates_skipped 列出跳过项；实际 orders/costs/allocations/issues 只保留本次新保存的订单。自动Excel接口仍返回 status=imported 及 result。
