# 标准Excel导入及动态利润展示设计

状态：待设计评审。日期：2026-10-17。首版目标：导入配套成本和每日文件，保存一个订单子项的数据版本，按模拟日期查看进度、累计利润及偏差来源。本文是设计，不代表功能已实现。

## 1. 已确定的需求

- 成本文件采用A-ORDER-0.2，只有成本计算、订单信息、原订单用量、补单用量四张工作表。
- 每日文件采用AB-TIME-0.2，含每日生产、每日材料、每日费用，记录当日增量。
- 一次导入完整周期；实际结果按发生日期及Asia/Shanghai可见时间逐日释放，不提前读取最终利润。
- 整单理论最大利润是固定目标。同进度理论利润按已经完成的合格产量计算，实际利润由同期原始收入和成本形成。
- 区分理想上界和含报价损耗预算的预期基线。默认以理想上界对照，切换时明确标签。
- 补产已包含于每日加工量、补料已包含于实际净耗。补单只作关联追溯，不再加收入、加产量或加费用。
- 数量和成本缺失不能转为0。材料价格、耗用、人工、能源及舍入影响须合计回利润差距。
- 首版验证单订单单子项。可以保存多个独立导入订单，但不实现多子项整单汇总、共享费用池或多人并发协作。

## 2. 现状及方案选择

目前serve.mjs只提供静态文件，dist/data.js返回内置24笔模拟订单；dist/metrics.js使用浮点数、固定2026年10月日期和材料/人工/能耗三类成本，不能作为本次导入的权威核算服务。

备选方案：浏览器内解析并保存IndexedDB，启动轻但不利于统一A计算和成员协作；沿用Node本地服务接收Excel、计算并保存数据，前后端边界明确；立即引入独立数据库和后端框架，扩展性较强但首版运维负担大。

采用第二种：现有Node服务增加独立导入、存储和计算模块，浏览器只负责文件选择、预览和展示。首版本机JSON不可变版本保存，为后续B数据库实现提供相同的存储接口。仅绑定127.0.0.1，不改变为局域网服务。

Excel解析和精确小数采用维护中的Node库，不自行实现通用Excel计算引擎。依赖必须锁定版本、具备许可证记录；具体库和打包命令在实现计划中确定。运行包包含必要运行依赖或构建产物，维持双击启动；缺依赖要给出明确提示，不能只关闭CMD。

## 3. 页面流程

新增侧栏“数据导入”，现有“订单详细数据”增加入口。

1. 两个文件位：成本Excel、每日Excel；均只接受.xlsx。显示文件名及大小。
2. 点击“解析并预览”，服务端识别结构并返回订单、子项、基线、修订、日期范围、生产/补单/材料/费用行数及模拟标记。
3. 预览显示概况、分码与每日记录、材料费用和校验问题。问题定位到文件类型、工作表、单元格、字段和记录ID。原始输入与计算结果分开。
4. 结构或业务冲突时不允许保存。仅资料缺失时允许“保存为待补齐版本”，受影响利润为空；有效数据可以正式导入。
5. 点击确认后整批原子保存；成功进入该订单分析页。失败保留文件选择和预览，不显示虚假成功。

不在导入确认前改写已存订单。切换文件会使旧预览失效。请求期间禁用重复按钮，展示进度文字；预览失效后可重新解析。

## 4. 文件识别与规范化

按模板版本、字段名及命名Excel Table识别，不靠文件名或黄色填充定位。订单信息按字段名读取。支持已提供的v0.2模式，v0.1或其他格式明确提示不支持，不静默猜测。

成本原始输入：订单元数据、配方数量和参考采购价、分码合同量、CostParameters参数、SupplementEvents关联。原订单用量中的模拟单价及SOP展示、成本计算结果、每日文件的核对列都由程序独立重算，忽略缓存。

本版报价比例校准BOM规则固定：目标均价=报价×材料占比÷统一标准重量，校准系数=目标均价÷参考配方加权均价，模拟材料价保留6位。原表SOP只是参考。本模式不冒充真实采购价；实际采购价及净耗读每日材料。

原始必填输入若是公式单元格则拒绝，不能依赖公式缓存或执行外链。允许模板计算区存在公式，但导入器不读取这些结果作为原始输入。Excel1900/1904日期系统均需明确处理；编号保留文本，Excel时间按订单时区解释。

规范化对象包含：order、baseline、revision、productionRecords、supplementEvents、materialRecords、expenseRecords及sourceRefs。钱和精确数量在API中用十进制字符串；双数为整数。每条来源保存文件类型、原文件摘要、工作表和单元格。实际文件名称只作为显示信息。

## 5. 校验、缺失与重复

阻止保存的错误：模板/表缺失、版本不兼容、跨文件订单或基线修订不一致、无效日期、未知材料/码号、重复记录ID/日码、负数或小数双数、不良大于加工、分码合同量与订单量不一致、补单关联错误、必填输入公式、无效枚举、混合币种/单位或不支持的补单计入方式。

可保存为待补齐：覆盖区间缺日码、材料净耗或费用记录缺失、未知期初或相关确认状态不足。生产进度完整时可展示；关键成本缺失时相关毛利为空；经营费用缺失只影响经营利润。每个结果返回完整性和具体缺项，不把SUMIFS为0视为已确认。

同订单/子项/基线/修订规范化内容相同，重复确认返回已有版本；同版本内容不同返回409，要求新修订号。新修订保存不可变快照，旧版可选择查看，不静默追加日数量。相同订单修订改变合同或基线内容必须使用新的基线ID，防止覆盖冻结预期。

补单与不良总数不同作为警示保留，不强行改齐；全周期超产另显示，不截断原始数量。文件中已有未来数据不属于错误，但查询时必须排除。

## 6. A模块计算与时间语义

独立纯函数负责标准输入计算，禁止由UI生成利润。范围为选定版本在模拟日末可见的记录；完整性覆盖从订单开始到该日的所有有效码号自然日。

- 日合格量=加工量−不良量，收入=合格量×净报价−同范围明确扣减；本案例扣减明确为0。
- 材料以actual_net×实际价逐日逐材料计；人工和其他费用从实际费用记录归集。制造费用标明模拟直接归属，不冒充正式工时分摊。
- 理论材料以相同合格量×标准重量×配方占比×基线价；人工、生产管理和能源按冻结参数生成同进度参照。
- 管理、销售、财务在生产毛利之后扣除。未结算不展示正式“最终实际利润”。
- 理想上界不扣损耗预算；预算基线另扣报价收入×预算费率，页面选择和响应均带baselineMode。
- 使用精确小数，重量/单价6位，逐材料和费用金额ROUND_HALF_UP至分，再累计。整单一次计算与逐日累计的舍入差单独展示。
- 价格影响=实际量×价差；用量影响=量差×基线价；人工及能源=实际−理论；舍入残差单列。实际−理论利润采用负值表示少赚，差距分解采用正成本增加值，响应明确符号。

日期早于开工时展示未开工、累计数量0、利润暂未发生，不评风险。截止早于某记录的可见时间时排除该记录并提示未齐；停产数量0仍可有已归属成本。当日收入0时毛利率为空，不能禁止负毛利金额存在。

## 7. B模块存储与本地API

新增server/import、server/profit、server/storage等独立职责，serve.mjs负责静态和API分发。前端数据服务通过适配器区分内置演示与已导入数据，不把导入记录强塞到旧演示公式。

首版API前缀使用/api/import-v1，与现有尚未实现的/api/v1三模块契约区分：

| 路径 | 行为 |
| --- | --- |
| POST /previews | multipart两文件；返回previewId、识别摘要、问题及预览；不保存订单 |
| POST /previews/{id}/commit | 确认同一预览及内容摘要；有效或明确待补齐状态；返回orderId、revisionId和重复状态 |
| GET /orders | 列出已导入订单及有效修订摘要 |
| GET /orders/{id}/revisions | 查看本地不可变修订版本 |
| GET /orders/{id}/analysis?revision=...&asOf=...&baselineMode=ideal | 返回当日/累计、理论目标、偏差桥、来源及完整性 |
| GET /orders/{id}/trend?revision=...&start=...&end=...&baselineMode=... | 每日日期点，与analysis同一计算路径 |

首版只保存规范化输入和摘要，不长期保留上传原文件。内存预览10分钟过期，确认时重新检查有效性；保存位于被Git忽略的data/imports目录。服务器生成文件ID，不使用上传文件名拼路径。写临时文件后原子重命名；提交队列串行保证冲突检查与写入一致，失败不发布半份数据；重启后恢复已存版本，过期/重启丢失预览提示重新解析。

接口属于本机联调适配层，未来B可替换存储、接入完整快照API；A不直接操作文件存储，C后续只读取结果和证据。

## 8. 导入后的展示

工作区切换“内置演示/已导入数据”，默认保留现有演示，首次导入成功自动选择已导入工作区。真实资料、引用原表生成的模拟案例和内置演示都有明确标识，不自动合并汇总。

已导入工作区日期范围来自所选订单覆盖区间；去除对2026年10月的硬编码。多订单时日期取覆盖并集，每笔按自身期间处理；仅展示可比结果合计及被排除数量，不称完整组合利润。

订单页显示：整单理论最大生产毛利、截至当天累计实际生产毛利、同进度理论毛利、利润差距；经营利润单列。曲线只展示截至选定日，未来计划可另标，但不能出现未来实际点。提供上一天/下一天、日期选择，首版不必实现自动播放。

明细显示生产、补单关联、材料和费用四类；差距图显示价格、耗用、人工、能源和舍入项，点击查看来源。缺失及暂估提示与结果同行。内置演示原有风险规则不自动成为导入订单的业务规则；首版显示偏差及数据质量，不虚构已确认风险阈值。

## 9. 文件边界和启动兼容

每文件上限10MiB，整个请求25MiB；每工作簿最多100000输入行；ZIP解压总量最多100MiB，超过即拒绝。非.xlsx、加密、损坏、宏格式及不支持的外链输入给明确错误。限制并发解析数为1，其余返回忙碌提示，不无限排队耗内存。

只接收本站同源请求，写接口检查Origin和启动时生成的页面令牌；验证上传不会把本地服务变成任意第三方页面的写入口。所有用户文本转义显示。静态文件路径检查改用path.relative判断确实位于dist内；data目录没有静态路由。

保留启动器等待就绪、重复复用、端口回退和中文空格路径测试。发布包可在Node20环境直接双击启动，不要求安装Excel、Python或数据库。原企业文件及完整案例不放进Git；CI使用纯合成小样，完整本地案例做人工验收。

## 10. 验收标准

1. 成本四表、每日三表可识别并预览；解析失败不改写旧数据。
2. 完整本地案例控制量为加工108636、不良8136、合格100500、补单8040；96差异警示，补单不重复归集。
3. 与已生成逐日验收JSON核对四个日期，金额精确到分；最终同进度理论毛利313218.18、模拟实际毛利176146.26，少赚137071.92；归因合计守恒。整单一次计算的理论目标313218.30与逐日累计相差0.12须展示舍入说明。
4. 切换到前一天只见前一天可见记录，完整周期文件不泄露未来实际曲线；补录可见时间晚于发生日期时正确处理。
5. 停产0、缺日、缺材料、缺生产费用、缺经营费用、零收入、负毛利、重复版本冲突、同版幂等和新修订均有测试。
6. 重启服务保留已导入数据；保存失败无半份数据；旧版本可查询。
7. 浏览器验证选文件→预览→确认→日期推进→明细追溯；已有演示页面与启动回归保持通过。
